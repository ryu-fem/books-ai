# بوت تليجرام لمكتبة الكتب

بوت يخليك (كمالك) تضيف كتب (ملفات PDF أو أي نوع)، ولما حد في الجروب يكتب حاجة زي
"عايز رواية كذا" أو "محتاج كتاب كذا"، البوت يدور على أقرب كتاب لعنوانه المطلوب
ويبعتهوله تلقائي في الجروب.

## 1) التجهيز

```bash
pip install -r requirements.txt
```

## 2) اعمل بوت من BotFather

- افتح تليجرام وابحث عن @BotFather
- ابعتله /newbot واتبع الخطوات، هياديك **TOKEN**
- عرف الـ ID بتاعك (ايدي حسابك الشخصي) عن طريق بوت زي @userinfobot

## 3) شغل البوت

```bash
export BOT_TOKEN="التوكن اللي أخدته من BotFather"
export OWNER_ID="ايدي التليجرام بتاعك"
python bot.py
```

## 4) إضافة الكتب

- في الخاص مع البوت (مش في جروب): ابعت ملف الكتاب وحط **اسم الكتاب** في الكابشن
  بتاع الملف، البوت هيضيفه تلقائي.
- أو رد على ملف مبعوت بالأمر: `/addbook اسم الكتاب`

أوامر تانية للمالك بس:
- `/listbooks` : يعرض كل الكتب المتضافة بأرقامها
- `/delbook 3` : يمسح الكتاب رقم 3

## 5) استخدام البوت في الجروب

- ضيف البوت للجروب واديله صلاحية قراءة الرسائل (وتقدر تديله صلاحية admin
  عشان تتأكد إنه شايف كل الرسائل لو الجروب فيه إعدادات خصوصية).
- أي عضو يكتب جملة فيها كلمة زي: "عايز"، "عاوز"، "محتاج"، "ابحث عن"، "دور على"،
  "ممكن كتاب"، "فين كتاب"، "عندك كتاب" ..إلخ متبوعة باسم كتاب قريب من اسم
  متضاف، البوت هيبعت الملف تلقائي كرد على رسالته.
- تقدر تزود/تعدل الكلمات دي من متغير `TRIGGER_PHRASES` في bot.py.
- تقدر تتحكم في دقة المطابقة من متغير `MATCH_THRESHOLD` (كل ما الرقم أعلى كل
  ما البحث يبقى أدق لكن أقل تسامح مع الأخطاء الإملائية، والعكس صحيح).

## 6) الرفع على GitHub

```bash
cd telegram_book_bot
git init
git add .
git commit -m "Telegram book bot"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO_NAME.git
git push -u origin main
```

(اعمل الـ repo الأول من على github.com بضغطة "New repository"، وحط رابطه بدل
`USERNAME/REPO_NAME` فوق. متنساش إن ملف `.gitignore` هيمنع رفع `books.db`
و`.env` بتاعتك عشان متسربش التوكن بالغلط.)

## 7) الرفع على Railway

1. ادخل على railway.app وسجل دخول بحساب GitHub.
2. اعمل **New Project** ← **Deploy from GitHub repo** ← اختار الريبو اللي رفعته.
3. Railway هيكتشف إن المشروع Python ويستخدم `Procfile` (اللي فيه
   `worker: python bot.py`) تلقائي. لو معملش كده، من تبويب **Settings** حط
   Start Command يدوي: `python bot.py`.
4. من تبويب **Variables** ضيف:
   - `BOT_TOKEN` = التوكن بتاع البوت
   - `OWNER_ID` = ايدي التليجرام بتاعك
5. اعمل Deploy. من تبويب **Deployments** تقدر تتابع الـ logs وتتأكد إن ظاهر
   "البوت شغال...".

### ملاحظة مهمة عن قاعدة البيانات على Railway

الفايل `books.db` بيتخزن على الـ filesystem العادي، وده على Railway ممكن
يتمسح لو عملت Redeploy جديد (الـ filesystem مش دايم/ephemeral). عشان تحافظ
على الكتب المتضافة بين الـ deployments، لازم تضيف **Volume** — الشرح
بالتفصيل في القسم اللي بعده مباشرة.

### إضافة Volume على Railway (شرح كامل خطوة بخطوة)

الـ Volume ده مساحة تخزين دايمة بتتحفظ حتى لو عملت Redeploy أو حتى لو
البوت وقع وشتغل تاني. من غيرها، فايل `books.db` بيتمسح كل ما تعمل نشر جديد.

**الخطوة 1: افتح المشروع على Railway**
- ادخل على railway.app وافتح المشروع بتاع البوت اللي عملته.

**الخطوة 2: افتح تبويب Service بتاع البوت**
- هتلاقي على يمين الشاشة (أو تحت حسب شكل الواجهة) كارت باسم السيرفس بتاعك
  (عادة بيبقى اسمه زي اسم الريبو). دوس عليه عشان تفتح تفاصيله.

**الخطوة 3: روح لتبويب Settings**
- جوه صفحة السيرفس، فوق هتلاقي تابات زي: Deployments, Variables, Settings,
  Metrics... دوس على **Settings**.

**الخطوة 4: دور على قسم Volumes**
- انزل لحد ما تلاقي قسم اسمه **Volumes** (أو زرار "Add Volume" / "New
  Volume" حسب نسخة الواجهة عندك).
- دوس على **+ Add Volume** أو **New Volume**.

**الخطوة 5: حدد مكان الـ Mount**
- هيطلبلك تحط **Mount Path** (يعني المسار جوه الكونتينر اللي هيتخزن فيه
  الداتا الدايمة). اكتب:
  ```
  /data
  ```
- مش لازم تحدد حجم كبير، الحجم الافتراضي كفاية جدًا لملف SQLite صغير
  (فايل الكتب عادة بيبقى كيلوبايتات قليلة، الملفات نفسها متخزنة كـ file_id
  على سيرفرات تليجرام مش عندك).
- احفظ (Save / Add).

**الخطوة 6: اربط متغير البيئة DB_PATH**
- روح لتبويب **Variables** بتاع نفس السيرفس.
- ضيف متغير جديد:
  - Name: `DB_PATH`
  - Value: `/data/books.db`
- احفظ.

> ملحوظة: الكود بتاعي في `database.py` بقى بيقرأ المسار من متغير البيئة
> `DB_PATH` (ولو مش موجود بيرجع لـ `books.db` العادي كـ افتراضي)، وكمان
> بيعمل إنشاء المجلد تلقائي لو مش موجود، فمش محتاج تعمل حاجة تانية في الكود.

**الخطوة 7: أعد النشر (Redeploy)**
- روح لتبويب **Deployments** ودوس على أحدث Deployment، وبعدين زرار
  **Redeploy** (أو ممكن يعمل ريستارت لوحده لو الـ Volume اتضاف وده بيغير
  إعدادات السيرفس).
- تابع الـ Logs وتأكد إنك شايف "البوت شغال..." من غير أي errors.

**الخطوة 8: اختبر إن الداتا فعلاً بتتحفظ**
- ابعت كتاب للبوت في الخاص عشان يتضاف.
- روح لتبويب Deployments واعمل **Redeploy** يدوي تاني (تجربة).
- بعد ما يخلص، ابعت `/listbooks` في الخاص وشوف هل الكتاب لسه موجود؟ لو
  ظاهر، يبقى الـ Volume شغال صح ومعمول ربط تمام.

بكده أي كتاب تضيفه هيفضل محفوظ للأبد حتى لو عملت تحديث للكود أو Redeploy
كتير مرات.

## ملاحظات مهمة

- المطابقة هنا بتستخدم خوارزمية تشابه نصوص (rapidfuzz) وده بيدي نتيجة كويسة
  جدًا وسريعة من غير ما تحتاج تدفع فلوس على أي API خارجي. لو حبيت مطابقة
  أذكى شوية بمعنى الجملة (مش بس تشابه الحروف)، ينفع بعدين نضيف نموذج
  embeddings (زي OpenAI/Anthropic أو نموذج محلي) ونقارن بالمعنى مش بالشكل بس،
  قولي لو عايز الإضافة دي.
- خلي بالك إن مسؤوليتك إنك ماترفعش/توزعش محتوى بشكل يخالف حقوق النشر أو
  قوانين بلدك.
- الملف `books.db` هو قاعدة البيانات (SQLite) اللي بتتخزن فيها الكتب، خليه
  محفوظ ومتعملوش حذف غير لو عايز تصفر البيانات.
